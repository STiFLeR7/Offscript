# INTERFACE COMPOSITION-WEBSITE — The Cognitive Engine of the Website Foundation

> **What this is.** The first layer of the Website **Foundation** — the constitutional parent of every
> realization model that follows it (Typography, Color, Motion, Shape, Surface, Grid, Components, Tokens,
> and any future discipline). It governs the one thing none of those models govern alone: the
> **interface-level judgment** through which they collectively produce one coherent, intentional,
> trustworthy, calm, sophisticated, high-quality interface. **Interface Composition is the only Foundation
> document whose primary responsibility is to cultivate intelligence rather than define a realization
> discipline. Every other Foundation model specializes this intelligence within its own domain.** Its
> output is not a page, a style, or a system; it is **interface design judgment** — the *Interface
> Composition Model* — that every downstream realization model inherits before it teaches its own craft.
>
> **What this is not.** Not typography, color, motion, grid, spacing, component, or token documentation.
> Not CSS, HTML, or framework guidance. Not an accessibility implementation guide, a pattern library, a UI
> kit, or a style guide. And — the subtler trap — **not a design article**: not a tour of techniques, not a
> catalogue of best practices, not an essay about good taste. It names no value and prescribes no
> realization. Those belong to the realization models beneath it. This document builds **judgment**, not
> knowledge.
>
> **The one boundary above all others.** *Interface Composition cultivates the cross-system judgment
> through which every Foundation realization model composes one coherent interface. It receives the
> settled upstream Models as binding truth and the Experience Character as the identity to serve; it
> re-decides none of them and sets no value of its own. It owns the way the Foundation reasons, and nothing
> else.* Everything in this document descends from that sentence.
>
> **The test every line passes.** *Does this paragraph cultivate judgment — or does it decide a value, or
> re-decide a Model an upstream layer already settled?* If it sets a value, it has leaked downward into a
> realization model. If it re-decides space, mechanism, perception, or progression, it has leaked upward
> into governance. Only what teaches a realization system **how to reason in context** belongs here. A
> second test governs endurance: *would this judgment remain valid after a complete redesign — a new visual
> language, a new technology, a new interaction paradigm?* **The intelligence developed by this document
> should remain valid regardless of future realization technologies, visual trends, or interaction
> paradigms.** If a statement depends on a particular look or technique, it is realization, not judgment,
> and it has been removed.
>
> **How to read it.** Each section develops a stage of design intelligence and states the reasoning beneath
> it, so the judgment can be applied in situations this document never anticipated. Read it as a curriculum
> that *builds* — perception before evaluation, evaluation before realization — not as chapters to consult.
> When two principles tension, the **Non-Negotiables (§18)** resolve the conflict.
>
> **Where this sits.** Below `PURPOSE.md`, `PHILOSOPHY.md`, `COMMUNICATION_AND_PERCEPTION_SYSTEM.md`,
> `INFORMATION_ARCHITECTURE.md`, `PAGE_STRUCTURE.md`, `SECTION_LAYOUT.md`, `COMPONENT_SYSTEM.md`,

> Information Architecture → Layout → Component → Visual* — ends at the "Visual" node, and Brand Expression

> stack beneath Brand Expression** — the parent of the Foundation's realization models, above
> Implementation. **On any conflict, every layer above wins over this document, and this document wins over
> every realization model below it.** Interface Composition realizes the Experience Character; it never
> co-authors it.

## §0 — First principles

Begin from nothing and reason up.

By the time the stack reaches this point, every objective truth about the experience is settled and a
single creative identity has been chosen. Communication has decided what must be understood and believed;
Information Architecture, what information must exist; Page Structure, how it unfolds; Section Layout, how
it occupies space; the Component System, how it becomes consumable; Visual Language, how it becomes
perceptible; and Brand Expression has discovered the one Experience Character every discipline must serve.
Nothing about *who the experience is* remains open.

And yet a coherent interface is still not guaranteed. Hand that complete, settled governance and that one
identity to the realization models — typography, color, motion, spacing, grid, components, tokens — and let
each define its discipline correctly in isolation, and the result can still fail. Every system can be
individually excellent and the interface still feel template-driven, mechanical, and emotionally flat. The
type is right, the spacing is right, the motion is right, and the whole reads as a collection of correct
parts rather than one intentional experience.

What is missing is not more knowledge in each discipline. It is the **judgment to compose** — the
intelligence that lets independent systems cooperate so the interface is perceived as one designed thing.
That judgment is what this layer exists to cultivate, and cultivating it is a different act from
documenting a discipline.

This reframes the entire Foundation. **The Interface Composition Model is not responsible for producing
better interfaces directly. It is responsible for producing better designers within the Foundation. Every
downstream realization model should become more perceptive, more context-aware, more system-aware, and more
capable of resolving design trade-offs because it inherited this model. If a realization model only becomes
more knowledgeable but not more discerning, the Interface Composition Model has failed.**

Everything that follows exists to develop that discernment — to teach the Foundation not what to know, but
how to think.

## §1 — Mission

**Interface Composition is the cognitive engine of the Website Foundation.** Its responsibility is not
merely to *contain* interface design judgment but to **progressively develop it** throughout the
Foundation. Every downstream realization model inherits its *way of thinking* before it inherits any domain
knowledge of its own.

Because every other Foundation model defines a discipline and this one defines a mind, its output is not a
discipline:

> *Interface Composition does not output a page, a style, or a system. It outputs interface design
> judgment — the **Interface Composition Model** — that every Foundation realization system inherits.*

This mirrors the layers above: each produces a governed model and hands it on. Interface Composition
produces the Interface Composition Model and hands it to Typography, Color, Motion, Shape, Surface, Grid,
Components, and Tokens, each of which specializes that judgment within its own domain. It is the
**first Foundation artifact** — the inherited intelligence that exists before any realization begins.

What the layer cultivates must be named precisely, so that "judgment" never softens into a motivational
word:

> **Design judgment is the ability to recognize competing design forces, evaluate their consequences,
> prioritize the most meaningful relationships, and select the realization that best reinforces the
> complete interface while remaining faithful to governance.**

And one distinction must be fixed before the document goes further, because the whole project depends on it:
**Judgment is the capability; decisions are its outcomes. The purpose of this document is to cultivate
better judgment so that better decisions naturally emerge. The document should therefore improve the
quality of reasoning rather than prescribe individual decisions.** A document that spent itself listing
good decisions would teach knowledge; this one teaches the faculty that produces good decisions on its own.

## §2 — The core question

Everything in this layer exists to answer a single constitutional question, and every section is measured
by how much it strengthens that answer:

> **How should every realization system cooperate so that the interface is consistently perceived as one
> intentionally designed experience rather than a collection of independently correct decisions?**

The phrase that matters most is *independently correct*. The failure this layer prevents is never a failure
of any single discipline; it is the failure of disciplines that are each right and together incoherent.
Coherence is not the sum of correct parts — it is a property that exists only between them, and only
judgment can produce it. Hold this question against every principle that follows: if a passage does not
make the cooperation between systems more intelligent, it does not belong here.

## §3 — What this layer receives

Interface Composition reads the complete Website Governance output. Four inputs are load-bearing:

- The **Experience Character Model** (from Brand Expression) — the one creative identity the interface must
  become.
- The **Spatial Model** (from Section Layout) — how the experience occupies space, and the relationships
  and hierarchy already settled there.
- The **Mechanism Model** (from the Component System) — how the experience becomes consumable.
- The **Visual Model** (from Visual Language) — how the experience becomes perceptible.

These arrive in two different capacities, and the difference is constitutional. The three objective Models
— Spatial, Mechanism, Visual — are inherited as **binding, settled truth, read for fidelity**: Interface
Composition realizes them coherently and never re-opens them. The Experience Character Model is the **sole
creative identity** the layer serves. This is why the layer can name space, mechanism, and perception in
its reasoning without owning them: it is teaching the Foundation how to *realize* what those Models already
decided, not deciding it again.

This honours the seam above it exactly. Brand Expression establishes that the Foundation consumes the
Experience Character Model and performs **no further creative interpretation**. Interface Composition
performs none: it interprets no identity, invents no brand, and re-decides no governance. Reading the
objective Models as inherited truth is not reinterpretation — it is fidelity. **Interface Composition
defers to that seam; it does not amend it.**

## §4 — The transformation

The layer performs one transformation, and its output is judgment, not implementation:

> **Website Governance → Interface Design Judgment → Compositional Intelligence → Foundation Thinking**

Settled **Website Governance** is read as the complete account of what the experience must be. From it the
layer cultivates **Interface Design Judgment** — the faculty defined in §1. That judgment, applied across
cooperating systems, becomes **Compositional Intelligence** — the ability to make many systems read as one.
And that intelligence, inherited by every realization model, becomes **Foundation Thinking** — a shared way
of reasoning that makes the whole Foundation more discerning. Nothing in this chain produces a value, a
file, or a rendered interface. The product is a mind the Foundation reasons with.

## §5 — How intelligence is built: the cognitive progression

This document develops judgment the way a designer develops it — in stages, each one making the next
possible. That progression is the organizing logic of the layer, but it must not be mistaken for a table of
contents:

> **The cognitive progression represents the evolution of design judgment rather than the organization of
> document content. It describes how interface intelligence develops, not how the markdown should be
> structured. The generated document should naturally cultivate these mental abilities throughout its
> explanations rather than mechanically allocating one chapter to each stage.**

The stages, as the maturation of a designer's mind — ending one level above refinement, where judgment
turns on itself:

> **Perceive → Understand → Interpret → Compose → Evaluate → Critique → Refine → Meta-Judge**

Two behaviours run through every stage and are repeated deliberately, because they are how the rest of the
document should be read.

**Relationships before objects; judgment before rules; intelligence before knowledge.** A realization
system reasons about elements through their relationships, not in isolation; it treats rules as the support
of judgment, never its replacement; and it values the faculty of reasoning above the accumulation of facts.

**Emergence.** The qualities this Foundation is built to produce are never manufactured and never inserted;
they **emerge**. Hierarchy emerges, calmness emerges, balance emerges, trust emerges, high quality emerges
— in the same way the Experience Character was *discovered* rather than invented. An interface that has been
assembled from isolated techniques will always read as assembled. So every concept in this document is
taught as something that *arises from sound reasoning*, never as a thing to apply: how hierarchy emerges,
not where to put it. From this follows the constitutional meaning of the word the rest of the stack reaches
for: **premium quality is never inserted through luxury aesthetics or isolated refinement. It emerges when
hundreds of individually sound decisions reinforce one another without contradiction.** (A wording
discipline follows from this: in its own reasoning the Foundation should speak of a *high-quality* or
*compositionally coherent* interface, and reserve *premium* for the *perceived* result — what the interface
feels like — because quality is a timeless property and premium is only its impression.)

## §6 — Perceive: human perception

Judgment begins in perception, because an interface is not what it contains — it is what a person
perceives.

The realization models inherit, first, an understanding of how humans actually read an interface: how
attention is drawn and distributed, how the eye scans before it reads, how nearby elements are grouped into
wholes, how the familiar is recognized faster than the novel, how cognitive load accumulates and exhausts,
how expectation shapes what is seen, how visual memory carries an impression from one screen to the next,
and how pattern recognition lets a person grasp structure at a glance. The aim is not academic psychology;
it is the perception that improves judgment — the ability to predict what a real person will notice,
overlook, group, and remember *before* a single value is chosen.

A realization model that reasons from perception asks what the interface will *do to a viewer*, not merely
what it contains. That single shift — from composing objects to composing an experience of being perceived
— is the foundation every later stage is built on. Without it, the rest is decoration.

## §7 — Compose: compositional intelligence

The concepts a person perceives an interface *through* — attention distribution, hierarchy, relationships,
rhythm, density, balance, continuity, unity — are the shared vocabulary of composition. They are
**interface-wide**, not the property of any one discipline, and the realization models **inherit them here
and never redefine them**. Typography does not invent its own hierarchy and color does not invent its own
balance; each specializes one shared idea. And in keeping with §5, each of these is taught as something that
**emerges**: the Foundation learns *how hierarchy emerges*, *how rhythm emerges*, *how balance emerges* —
never how to install them.

Three refinements give this stage its discernment.

**Relationship priority.** Relationships themselves possess a hierarchy. Some relationships define the
experience; others merely support it. A realization model must learn to recognize **primary, secondary, and
contextual** relationships *before* it tries to strengthen them, because compositional quality emerges from
reinforcing the *correct* relationships — not from treating every relationship as equally important.
Strengthening a contextual relationship at the expense of a defining one is how interfaces become busy and
unclear while every local decision looks reasonable.

**Temporal judgment.** A website is experienced **over time, not only in space**. Even before anything
moves, an interface has pacing, anticipation, moments of pause, acceleration, progression, and release — the
felt tempo of moving through it. This is interface *experience*, **not motion**: it is the judgment a
realization model needs in order to reason about how an experience unfolds, and it is inherited by Motion
and every other system, never owned here. Temporal judgment defers to the Progression Model, which already
governs how the page unfolds; it teaches reasoning about tempo, it does not re-decide progression.

**Compositional momentum.** Broader than rhythm is the question of momentum: does the interface keep
moving, slow down, pause, accumulate complexity, or reset attention? Momentum is the accumulation and
release of compositional energy across an experience — the judgment that makes a long, narrative page feel
like one journey rather than a stack of sections. Like temporal judgment, momentum is a way of reasoning the
realization models inherit; it defers to the Progression Model and to Motion and decides neither.

## §8 — Understand the qualities: interface qualities

The realization models inherit a clear understanding of the qualities a coherent interface possesses —
clarity, calmness, confidence, precision, restraint, intentionality, consistency, sophistication, harmony,
trust — and, crucially, an understanding that these are **not styles to apply but properties that emerge
from judgment**. Calmness is not a color; it is what a viewer feels when nothing competes for attention it
has not earned. Trust is not a badge; it is what accumulates when every decision proves consistent with the
last. A realization model learns to recognize these qualities, to know what produces them, and to know what
quietly destroys them — so it can reason toward them rather than decorate for them.

The deepest of these understandings is that an interface is a conversation. **Interfaces communicate through
a conversation between visual systems.** Typography introduces ideas; whitespace provides pauses; imagery
reinforces understanding; color guides emotional emphasis; components organize interaction. No realization
system communicates independently. A coherent interface emerges only when every system participates in the
**same visual conversation** — when type, space, image, color, and component are saying one thing together
rather than each speaking correctly over the others. This is the difference between an interface that is
*assembled* and one that is *composed*, and it is the practical meaning of the core question.

## §9 — Decide: constraint-based decision making

Knowledge tells a realization model what is possible. Judgment tells it what should happen. The bridge
between them is how it reasons inside constraints — and exceptional designers reason inside constraints very
differently from how rules are followed. **Constraints create coherence; judgment creates quality.** The
upstream Models and the Experience Character define the safe operating boundaries; within them, judgment
selects the realization that best serves the whole. The realization models inherit that way of reasoning,
expressed in six disciplines.

**Decision flow.** A realization decision **never begins with a value; it begins with understanding.** The
reasoning runs from situation, to objective, to the relationships in play, to the constraints that bind it,
to the context that colours it, to the decision, and only then to the realization. Realization is the
**final outcome of reasoning, never its starting point** — a type size, a spacing step, a color is what a
chain of understanding *concludes with*, never what it opens with. Every realization model inherits this
ordering.

**Trade-offs.** This is the heart of judgment. Senior designers rarely choose between good and bad; they
choose between **good and good** — more breathing room versus stronger continuity, greater hierarchy versus
greater calmness, visual drama versus reading efficiency. **Design judgment is fundamentally the ability to
resolve competing valid objectives.** That is a different and harder act than making a decision: it is
prioritization under tension. And its aim is balance, not maximization — **the objective is not to maximize
every quality simultaneously; it is to discover the most appropriate balance for the current context.** An
interface that maximizes every quality at once maximizes none.

**Negative decisions.** The most overlooked move in design is subtraction. **Design judgment includes
recognizing when restraint creates greater quality than addition. Every realization model should learn that
choosing not to introduce visual complexity is an equally valid design decision.** Choosing not to add, not
to emphasize, not to separate, not to decorate is a decision in full standing — and it is most often the one
that produces calm.

**Evidence-based judgment.** Judgment must stay grounded, or it becomes invention dressed as reasoning.
**Every judgment should be traceable to constitutional inputs, contextual understanding, or compositional
reasoning; decisions should never rely on unexplained preference.** Stated as a working discipline: **every
judgment should be explainable — if the reasoning behind a decision cannot be articulated through
governance, context, relationships, or compositional intelligence, the decision should be reconsidered.**
This keeps the whole Foundation auditable: every realization can answer *why*.

**Context hierarchy.** Context itself has a hierarchy, and a realization model must know which context
outranks which. From most to least authoritative: **Experience Character → User Goal → Information Priority
→ Section Context → Local Element.** **Context closest to governance outweighs local optimization.** This is
what stops a model from perfecting a small detail in a way that quietly betrays the experience it belongs
to.

**Confidence hierarchy.** Not every decision carries equal certainty, and pretending otherwise makes a
system brittle. Some decisions are **constitutional** and should remain stable; some are **contextual** and
should adapt; some are **opportunistic** and may improve quality when the moment allows. A realization model
that can tell these apart knows what to hold and what to flex — and is far more resilient than one that
treats every decision as equally fixed or equally negotiable.

## §10 — Adapt: controlled elasticity

Consistency is not repetition, and this is the principle that proves it. A high-quality interface is neither
rigid nor arbitrary; it is **intelligently elastic** — it adapts to context while remaining unmistakably
itself. **Consistency means preserving identity while intelligently adapting to context, not repeating
identical solutions.** A section breathes more, a card expands, whitespace shifts, rhythm slows, emphasis
moves — and the interface stays one thing, because the adaptation served the context rather than escaping
the identity.

What makes elasticity *controlled* is knowing exactly what may flex and what may not. Three tiers remove the
ambiguity:

- **Hard boundaries** — governance, the Experience Character, purpose, and information truth. These never
  flex. They are the identity itself.
- **Soft boundaries** — spacing, rhythm, breathing room, emphasis, balance. These flex with judgment; they
  are *where* intelligent adaptation happens. (Naming them here is naming where adaptation occurs, never
  setting their values — the values belong to the realization models.)
- **Elastic regions** — local adaptation, contextual variation, compositional refinement. This is the room
  in which a realization model exercises judgment freely.

Two statements make the principle binding. First, its scope: **Controlled Elasticity is not limited to one
area of interface realization. It is the behavioural principle through which every Foundation model
intelligently adapts to context while remaining faithful to constitutional boundaries. Every downstream
realization model inherits this behaviour. It must never become a local concept.** Second, its limit:
**Controlled Elasticity is not permission to improvise. Every adaptation must remain explainable through
governance, context, and compositional reasoning. If a realization cannot justify why it stretched, it
should not stretch.** Elasticity is reasoned adaptation, never creative freedom.

## §11 — Reason across systems: systemic intelligence

The single largest upgrade this layer makes to the Foundation is to stop each model from optimizing itself.
A realization model that perfects its own discipline in isolation will routinely damage the interface, and
this section is the judgment that prevents it.

**Multi-system reasoning is bidirectional.** Every realization model must understand the influence its
decisions have on every other system **and the influence those systems have on it**: typography affects
spacing *and* spacing affects typography; color influences hierarchy *and* hierarchy changes how color is
perceived; motion changes rhythm *and* rhythm changes perceived motion. **No realization model optimizes
itself in isolation.** Stated as a rule the Foundation inherits: **a realization model should never improve
its own discipline while unintentionally weakening another; every optimization is evaluated for its systemic
consequences before it is accepted.**

**Degrees of influence.** Influence is not binary, and treating it as binary causes over-correction.
**Relationships between realization systems possess different strengths; the system should learn to
distinguish primary, secondary, and indirect influences rather than assuming every relationship carries
equal weight.** Typography bears on hierarchy far more than it bears on color; spacing bears on grouping far
more than on motion. Proportional reasoning keeps a model from over-adjusting one system to satisfy a weak
relationship with another.

**Second-order effects.** Every decision produces consequences beyond its immediate purpose, and judgment is
the habit of anticipating them. More spacing improves readability but can weaken grouping; more contrast
improves visibility but can weaken calmness; more emphasis improves attention but can reduce hierarchy
elsewhere. A realization model must **anticipate these consequences before committing to a realization** —
the immediate gain is never the whole result.

**Judgment accumulation.** Interfaces rarely fail because of one decision; they fail because of fifty
individually reasonable ones. Every realization decision **accumulates**, and so a realization model must
hold a long-range awareness and keep asking the only question that catches accumulation in time: **is the
interface becoming better, or merely more?** This is the discipline that separates a composed interface from
a crowded one.

**The local–global loop.** The method beneath all of this is the one expert designers run constantly — zoom
in, zoom out, repeat. *Observe the local problem → predict the global consequence → adjust locally →
re-evaluate globally → repeat until both improve.* A decision is finished only when it improves the part
*and* the whole at once.

## §12 — Critique: quality intelligence

A realization model must judge its own work before it produces anything, and it must judge it against the
interface, not against its discipline. This layer therefore cultivates an internal critic — the habit of
evaluation that runs *before* output, strengthening internal judgment rather than waiting for external
validation. The questions it inherits are interface questions, asked of every decision:

- Does this decision improve the overall interface, or only this part of it?
- Does it reinforce the Experience Character?
- Is hierarchy emerging naturally, or being forced?
- Is attention earned, or merely demanded?
- Is whitespace solving a relationship, or just creating emptiness?
- Is rhythm intentional, or accidental?
- Is this improving clarity, or adding noise?
- Does every realization strengthen the interface as a whole?
- Does this feel composed, rather than assembled?
- Does this decision make the experience feel inevitable?

Above this self-critique sit two faculties that complete the progression.

**Meta-judgment.** The highest critic does not only check the decision; it checks the reasoning. A
realization model must learn to **evaluate not only the quality of its decisions but the quality of the
reasoning process that produced those decisions. The goal is to continually improve how the system thinks,
not merely what it decides.** This is the one level above refinement — the difference between asking "did I
decide well?" and asking "am I using the right way of thinking for this problem?" A Foundation that can
question its own reasoning improves without limit.

**Design maturity.** And the rarest faculty is knowing when to stop. A realization model must **recognize
when the interface has reached sufficient coherence. Exceptional interfaces do not emerge from endless
refinement, but from knowing when further changes no longer improve the experience. The highest form of
judgment is often restraint.** Without this, intelligence turns into over-design — refinement that adds
motion without adding meaning. Maturity is the judgment that calls an interface done.

## §13 — The Foundation realizes; it inherits judgment first

Every realization model beneath this one — Typography, Color, Motion, Shape, Surface, Grid, Components,
Tokens — inherits the Interface Composition Model before it defines a single value of its own. The chain
within the Foundation is explicit:

> **Experience Character Model (with the Spatial, Mechanism, and Visual Models) → Interface Composition
> Model → Typography · Color · Motion · Shape · Surface · Grid · Components · Tokens**

Each realization model is a specialization of the same inherited judgment, not an independent authority.
Typography reasons typographically *with* this judgment; color reasons chromatically *with* it; motion
reasons temporally *with* it. None of them re-opens a concept this layer established — hierarchy, balance,
relationship, rhythm, emergence, trade-off, elasticity belong to the whole Foundation and are inherited, not
redefined, by each part.

One inheritance is singular and must be stated plainly. **Tokens must never become a decision-making
system.** A token is the operational representation of a decision already reasoned through — it **encodes**
judgment, it does not **generate** it. The moment tokens begin to make design decisions, the Foundation has
inverted itself: realization would be authoring identity, which is precisely what every layer above forbids.

## §14 — Why this layer exists (the removal test)

Remove Interface Composition and ask what survives. Every realization model still defines its discipline,
and each can do so impeccably. Picture it at its best: the **typography is excellent**, the **spacing is
excellent**, the **motion is excellent** — every system correct on its own terms.

And the interface still feels **template-driven, mechanical, and emotionally flat.** Nothing taught the
systems to cooperate; nothing made them participate in one visual conversation; nothing resolved the
trade-offs between them or weighed their cross-system consequences; nothing knew when to stop. The result is
exactly the failure named in the core question — *a collection of independently correct decisions* — and it
is invisible to each discipline, because no discipline owns the space between them.

That space is what this layer governs. It is the difference between a Foundation that produces correct parts
and one that produces a composed whole, and it cannot be recovered by making any single realization model
better. This is why Interface Composition exists, and why it must come first.

## §15 — What Interface Composition must never do

This layer's discipline is absolute, and it is defined as much by what it refuses as by what it cultivates.
Interface Composition is **never** any of the following, and each belongs to a model beneath it or a layer
above it:

- Typography, color, motion, grid, spacing, shape, surface, component, or token documentation.
- A value, scale, measurement, ratio, or any concrete realization of any kind.
- CSS, HTML, or framework guidance; any implementation technique.
- An accessibility implementation guide.
- A pattern library, a UI kit, or a component catalogue.
- A style guide, a brand sheet, a moodboard, or an art-direction document.
- A design article — a tour of techniques, a list of best practices, or an essay about taste.
- A re-decision of any upstream Model: it never re-opens meaning, information, progression, space,
  mechanism, or perception, and it never re-interprets the Experience Character.

If a passage in this document does any of these, it has left its altitude and must be removed. The layer
owns the judgment realization inherits, and nothing else.

## §16 — The signature hazards (leakage warning)

This layer is uniquely exposed to boundary blur, because the concepts it reasons about are owned, above it
or below it, by other layers. Four pressures recur, and each is a failure of altitude.

- **Leaking downward into a value.** The moment a sentence specifies a size, a step, a duration, a ratio, or
  a color, it has stopped cultivating judgment and started doing a realization model's job. Teach the
  reasoning; never name the number.
- **Leaking upward into governance.** Hierarchy, relationships, and space belong to the Spatial Model;
  perception belongs to the Visual Model; mechanism belongs to the Mechanism Model. When a sentence reads
  like a Section Layout rule or a Visual Language rule, it has re-decided settled truth. Reference those
  Models to *defer* to them and to teach reasoning about them — never to redefine them.
- **Temporal judgment becoming motion or progression.** Pacing, momentum, and tempo are judgment; the
  instant they become a motion specification or a re-decision of how the page unfolds, they have leaked into
  the Motion model or the Progression Model. Keep them as ways of reasoning.
- **Drifting into a design article.** The opposite failure: prose that is neither a rule nor a value but a
  pleasant essay about good design. It teaches nothing a realization model can reason with. Every paragraph
  must increase discernment, not admiration.

## §17 — Success criteria

A successful Interface Composition Model **permanently changes the behaviour of every downstream realization
model.** After inheriting it:

> **Typography optimizes the interface rather than typography; Color optimizes the interface rather than
> color; Motion optimizes the interface rather than motion; Components optimize the interface rather than
> components; and Tokens faithfully *encode* decisions rather than *generate* them.**

Three measures make this concrete.

- **The inheritance test.** *A successful Interface Composition Model produces downstream realization models
  that consistently reach compatible conclusions independently because they inherit the same judgment rather
  than the same rules.* Convergence without coordination is the proof that judgment — not a rulebook — was
  transmitted.
- **Systemic, not local.** Each realization model understands how its decisions influence hierarchy, rhythm,
  spacing, balance, color, motion, and the complete interface. The objective is **systemic coherence, never
  local optimization** — better cooperation, not better isolated disciplines.
- **The felt test.** *A successful Interface Composition Model produces interfaces whose quality is
  recognizable even before individual design decisions are consciously noticed.* People feel the quality
  before they admire the spacing. Such interfaces feel intentionally composed, calm, coherent, trustworthy,
  premium, sophisticated, and inevitable — never mechanically assembled, rigid, generic, template-driven,
  visually noisy, or technically correct but emotionally flat.

## §18 — The Non-Negotiables

When two principles tension, these resolve the conflict. They are the constitutional truths every
realization model inherits and may never override.

1. **Decision before definition.** Reasoning precedes values; understanding precedes realization.
2. **Relationships before objects.** No element is reasoned about in isolation, only through its
   relationships.
3. **Judgment before rules.** Rules support judgment; they never replace it.
4. **Intelligence before knowledge.** The Foundation is made more discerning before it is made more
   informed.
5. **Context before consistency.** Consistency preserves identity; it is never mechanical repetition.
6. **Controlled elasticity.** Adaptation is intelligent and explainable, bounded by the hard/soft/elastic
   tiers; it is never improvisation and never a local concept.
7. **Global coherence before local optimization.** *Every realization decision is evaluated not only through
   its local correctness but through its contribution to the complete interface. No realization model may
   optimize its own discipline at the expense of overall compositional quality. Local excellence must always
   reinforce global coherence.*
8. **Emergence.** Nothing is manufactured; quality emerges when sound decisions reinforce one another without
   contradiction.
9. **Judgment inherited, never re-decided.** Realization models specialize this judgment; they never reopen
   the concepts it establishes, and Tokens encode decisions rather than generate them.
10. **Boundary fidelity.** This layer sets no value, re-decides no upstream Model, and re-interprets no
    identity. It owns judgment, and nothing else.

## §19 — The final governing principle

> **The purpose of this document is not to teach the Foundation how to follow a design system. It is to
> teach the Foundation how the people who create exceptional design systems think. When it is complete, it
> should not merely make the Website Foundation more knowledgeable — it should make it significantly more
> intelligent. The moment a realization model inherits more rules but not more judgment, this layer has
> failed.**
