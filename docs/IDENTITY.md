# Versioned project identity

The engine's identity modules preserve selected reference qualities, approved identity snapshots and checked project inputs. They call no model or inference API. Reference interpretation, human approval and generation remain separate steps.

- `identity/direction.ts`: `directionPrompt` carries exact selected/rejected qualities and notes. `validateDirection` checks source-linked observations, interpretation and uncertainty. Executors must inspect actual images; a prompt or metadata is not visual evidence.
- `identity/identity.ts`: `approveIdentity` validates schema, UTC approval timestamp, CSS/voice and raw SHA-256 asset hashes, then returns a copied, frozen snapshot. `verifyIdentity` checks the snapshot digest and current asset bytes. Approval shape is validated; human authenticity must be established by the caller's explicit user action.
- `identity/identity-store.ts`: `saveIdentity` and `loadIdentity` persist immutable `(brandId, version)` records under an injected root. An identical save is idempotent; a conflicting version fails. Snapshot loading checks structure/digest, not external asset bytes.
- `identity/identity-materializer.ts`: `materializeIdentity` installs checked CSS, voice, assets and BrandContract into a supplied references directory. `readInstalledIdentity` verifies the installed snapshot and managed file bytes. Brief/source-doc content and unrelated files are preserved, including a source document that was previously a managed asset. Each asset is read into a buffer once, and the exact checked bytes are staged. BrandKit is emitted only for a checked light/dark mark pair; no fake pair is created for a text identity. Auto-derived contract mappings retain auto confidence and unmapped reasons.
- `identity/identity-approval.ts`: `recordIdentityApproval` records an explicit user's identity digest/version/mode in the existing project session log. It requires the exact installed identity and existing acquisition readiness, then persists refreshed readiness. It neither confirms audience/brand facts nor grants unrelated approvals. `isCurrentTextIdentityApproved` is the pure readiness helper.

Generation and acquisition use the runtime identity-readiness adapter. It recomputes installed verification and current context; a stored `verified` flag is not trusted at admission. Only a current, actor-bearing text approval matching verified installed bytes waives the logo requirement. Other evidence, approval and workflow gates remain. Marks mode requires actual mark assets, registered through the existing context asset-name contract. Managed identities require acquisition readiness and are checked even when that readiness file is absent; unmanaged projects retain the legacy path. Loading a readiness snapshot alone does not verify installed identity. Identity approval refreshes a workflow only if its entire persisted definition/state matches the default-derived plan; customized workflows retain their definitions and pending gates.

Identity ids use lowercase alphanumeric/hyphen/underscore names; existing safe project names may retain mixed case. Assets use safe relative paths. Linked ancestors, junctions, path escape and unowned target-file conflicts are rejected. Identity approval does not authorize publication. Store identity libraries, supplied assets and generated project material under ignored/private roots; source and test fixtures should contain only synthetic material.

Installation has an exclusive `.offscript-identity.lock` and stages changes within the references directory. If rollback itself fails, all remaining restorations are attempted, the lock records the recovery staging path, and backups are retained with an aggregate error. After an interrupted process or incomplete rollback, inspect the generated lock/process and staging backups before any manual recovery; never remove unknown project files to force installation. Consumers must treat an active install as unavailable. Keep source assets available for re-verification and do not edit managed files in place; create a new approved version.
